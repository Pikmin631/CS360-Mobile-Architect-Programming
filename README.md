# CS360-Mobile-Architect-Programming

Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?

The goal of this project was to develop a fully functional application that would track events for a client with Mobile2App development. The user needed a database for user information and stored events. The events were to be displayed on a grid layout where they could add, delete, and update events to then be notified by SMS. 


What screens and features were necessary to support user needs and produce a user-centered UI for the app?

I included a login/account creation screen, events screen, and an update/create events screen. users could login with an account they created and their events would be displayed in chronological order. 

How did your UI designs keep users in mind? Why were your designs successful?
A design choice I made at the beginning was to go with a dark theme. This was purposeful in that it is easier on the eyes. When designing my screens I tried to thin of how I could make the experience for a user memorable. After logging in, events were displayed in chronological order so it was easy to read. Times and details of each event were all visible for ease of use. 

How did you approach the process of coding your app? What techniques or strategies did you use? 
I used split view quite a bit when coding as I was able to design the applications layout exactly how I envisioned. My process was to start with the flow of the application like a timeline. The first thing the user will do when using my application is login or create an account. So my focus was on the login/create account screen. I would only continue to the next part of the flow when I was satisfied with the quality of the screen. When I was able to go through a full timeline of my application error free I was able to conclude the completion of my project. 

How could those techniques or strategies be applied in the future?
For future projects, I can apply strategies of following flow to ensure each component and piece is built properly. Testing was extensive to ensure each piece flowed cohesively. 


How did you test to ensure your code was functional? Why is this process important, and what did it reveal? 
I tested in small and controlled iterations. For example, When testing functionality of creating an event. I started with the FAB button, when pressed, opens the create event screen. Once that was successful I could move on to the next step of adding a title and description box to enter event information. I repeat this process of testing each functional action a user can do so that I know the app is serving its purpose. 



Consider the full app design and development process from initial planning to finalization. Where did you have to innovate to overcome a challenge?
One challenge was the calendar picker in that initially you could select any date even in the past and it would add to the grid layout list. I thought maybe a solution was to check the current date and not let the user save the event if the date was in the past. However, I later thought of a better idea to just grey out the calendar dates that are not valid so a user could only choose a valid date. 


In what specific component of your mobile app were you particularly successful in demonstrating your knowledge, skills, and experience?
I think overall I made a great UI designed application. My color layout was simple with dark grey and purple. The flow of the application was easy to follow and you were able to successfully create events on the fly and enable SMS notifications. I thoughtfully built each feature with ease of use in mind to give a high quality experience.
